## 현재 MVP 평가

현재 MVP는 교양서 중심 랭킹 서비스의 기본 골격을 갖추고 있다.

- 홈, 랭킹, 카테고리, 책 상세, 로그인, 마이페이지 화면이 구현되어 있다.
- backend에는 홈, 랭킹, 급상승, 카테고리, 책 상세, 마이페이지 조회 API가 준비되어 있다.
- 랭킹은 수험서와 전공서를 제외하는 `is_general_eligible` 기준을 반영한다.
- 마이페이지는 관심 분야, 읽은 책, 저장한 책, 추천 히스토리를 보여주는 구조를 갖추고 있다.

다만 README에서 강조하는 개인 맞춤 추천은 아직 제품 경험으로 충분히 닫히지 않았다.

- 홈 추천은 사용자 취향 기반이라기보다 기본 추천에 가깝다.
- 사용자가 관심 분야, 읽은 책, 저장한 책을 직접 입력하거나 관리하는 흐름이 부족하다.
- 책 상세에서 저장, 읽음, 관심 없음 같은 추천 개선 행동을 바로 남기기 어렵다.
- 검색 입력은 있으나 실제 탐색 기능으로 이어지는 경험은 아직 약하다.

따라서 현재 MVP의 가치는 "교양서만 추려 보는 랭킹"이고, 다음 단계의 목표는 "내가 읽을 책을 고르는 판단 도구"로 확장하는 것이다.

## UX 고도화 방향

UX 고도화의 핵심은 사용자가 서비스를 이해하는 시간을 줄이고, 행동할 때마다 추천이 좋아진다는 느낌을 주는 것이다.

우선 강화할 사용자 흐름:

1. 비로그인 사용자가 홈에서 교양서 랭킹과 급상승 책을 확인한다.
2. 책 상세에서 추천 이유, 키워드, 비슷한 책을 보고 판단한다.
3. 로그인 또는 회원가입 후 온보딩에서 관심 분야와 읽은 책을 입력한다.
4. 홈과 마이페이지에서 개인화된 추천 이유를 확인한다.
5. 저장, 읽음, 관심 없음 같은 행동이 다음 추천에 반영된다.

화면 설명은 길게 제공하기보다, 사용자가 필요한 순간에 짧게 보여주는 방식이 적합하다.

- 랭킹 화면: "수험서와 전공서를 제외한 교양서 기준 랭킹"
- 책 상세: "이 책이 추천된 이유와 비슷한 책"
- 마이페이지: "읽은 책과 저장한 책이 추천에 반영됨"

## 온보딩 및 튜토리얼 계획

온보딩은 단순 사용법 튜토리얼보다 추천 품질을 높이는 초기 설정 흐름으로 설계한다.

권장 온보딩 단계:

1. 관심 분야 선택
   - 인문, 경제, 자기계발, 소설, 에세이 등
2. 독서 목적 선택
   - 가볍게 읽기, 깊이 읽기, 트렌드 파악, 업무/성장, 투자/경제 이해 등
3. 최근 읽은 책 입력
   - 최소 1권, 권장 3권
   - 초기에는 기존 도서 목록 선택 방식으로 시작하고, 이후 검색 기반 입력으로 확장한다.
4. 제외하고 싶은 책 유형 선택
   - 수험서, 전공서, 지나치게 실용서 중심인 책, 너무 어려운 책 등
5. 첫 추천 결과 제공
   - 입력한 관심 분야와 읽은 책을 기반으로 첫 추천 리스트를 보여준다.

튜토리얼은 별도 긴 화면보다 첫 사용 시 짧은 안내로 제공한다.

- 홈: ChaekList가 일반 베스트셀러와 다른 기준을 사용한다는 점을 안내
- 랭킹: 조회, 저장, 상승률이 랭킹에 반영된다는 점을 안내
- 마이페이지: 입력한 정보가 추천에 반영된다는 점을 안내

## 마이페이지 정보 입력 계획

마이페이지는 단순 조회 화면에서 취향 관리 화면으로 확장한다.

추가할 정보 입력 항목:

- 관심 분야 추가, 삭제
- 독서 목적 수정
- 읽은 책 추가, 삭제
- 저장한 책 관리
- 추천에서 제외할 키워드 또는 도서 유형 관리

마이페이지에서 사용자가 기대하는 핵심 문장은 다음과 같다.

> 내가 입력한 독서 취향과 읽은 책을 바탕으로 추천이 바뀐다.

이를 위해 마이페이지에는 단순 목록뿐 아니라 추천 반영 상태를 보여주는 요소가 필요하다.

- 관심 분야별 추천 반영률
- 읽은 책 기반 추천 수
- 최근 추천이 바뀐 이유
- 비어 있는 섹션별 다음 행동 버튼

## 읽은 책 저장 및 추천 반영 계획

읽은 책 저장은 개인화 추천의 핵심 입력값이다.

우선 제공할 사용자 행동:

- 저장하기: 나중에 읽을 후보로 보관
- 읽었어요: 취향 분석에 강하게 반영
- 관심 없음: 유사 추천에서 제외하거나 가중치 하향

추천 반영 기준:

- 읽은 책의 카테고리
- 읽은 책의 키워드
- 비슷한 책과의 공통 키워드
- 저장했지만 아직 읽지 않은 책
- 관심 없음으로 표시한 책의 카테고리와 키워드

추천 이유는 사용자가 납득할 수 있게 구체적으로 표시한다.

- 나쁜 예: "경제 분야에서 인기 있는 책입니다."
- 좋은 예: "읽은 책 `조용한 투자 습관`과 투자, 습관 키워드를 공유합니다."

초기 구현은 콘텐츠 기반 추천으로 충분하다.
협업 필터링이나 유사 유저 추천은 사용자 행동 데이터가 쌓인 뒤 확장한다.

## 서비스 고유 기능 제안

ChaekList의 차별점은 단순히 교양서를 모아 보여주는 것만으로는 약하다.
서비스 고유 기능은 "교양 필터 리포트"와 "추천 근거"를 중심으로 강화하는 것이 좋다.

### 1. 교양 필터 리포트

책마다 왜 ChaekList 랭킹에 포함되었는지 보여준다.

- 교양서로 분류된 이유
- 제외 키워드가 없는 이유
- 주요 카테고리와 키워드
- 수험서, 문제집, 전공서 성격이 낮은 근거

### 2. 추천 근거 카드

추천 카드에 개인화 근거를 함께 표시한다.

- 관심 분야와의 연결
- 읽은 책과의 연결
- 저장한 책과의 연결
- 최근 독서 트렌드와의 연결

### 3. 읽을 책 결정 보조

책 상세에서 사용자가 빠르게 판단할 수 있는 정보를 제공한다.

- 이 책을 읽기 좋은 사용자
- 읽기 난이도
- 예상 독서 분위기
- 비슷한 책과의 차이

이 기능들이 쌓이면 ChaekList는 "랭킹을 보는 서비스"가 아니라 "읽을 책을 결정하는 서비스"가 된다.

## 단계별 우선순위

### 1순위: 개인화 입력 흐름 완성

- 회원가입 후 온보딩 진입
- 관심 분야 선택
- 읽은 책 입력
- 마이페이지에서 입력값 확인
- 비어 있는 섹션별 안내와 다음 행동 제공

### 2순위: 책 상세 행동 추가

- 저장하기
- 읽었어요
- 관심 없음
- 행동 결과를 마이페이지에 반영
- 저장/읽음 상태를 책 카드와 상세 화면에 표시

### 3순위: 추천 이유 고도화

- 관심 분야 기반 추천 이유
- 읽은 책 기반 추천 이유
- 저장한 책 기반 추천 이유
- 추천 히스토리에 추천 근거 저장

### 4순위: 서비스 고유 기능 강화

- 교양 필터 리포트
- 추천 근거 카드
- 읽기 난이도와 독서 목적 기반 안내
- 검색 기반 책 추가

### 5순위: 데이터 기반 추천 확장

- 행동 로그 기반 랭킹 개선
- 유사 도서 추천 개선
- 유사 사용자 추천
- 리뷰 또는 키워드 기반 감정 분석

## 남은 리스크와 후속 검토 사항

- 온보딩과 읽은 책 저장은 frontend, backend, DB schema를 함께 건드릴 가능성이 높다.
- 사용자 행동 데이터가 적은 초기에는 개인화 추천 품질이 제한적일 수 있다.
- 교양 필터 기준이 불명확하면 차별점이 약해질 수 있으므로 필터링 이유를 사용자에게 설명해야 한다.
- 책 데이터 수집 출처와 표지 이미지 품질이 낮으면 탐색 UX가 약해질 수 있다.
- 추천 이유가 추상적이면 개인화 기능이 체감되지 않을 수 있다.

후속 작업을 시작할 때는 다음 순서로 작은 단위 계획을 세운다.

1. 온보딩 화면과 입력 데이터 범위 확정
2. 사용자 관심 분야와 읽은 책 저장 API 설계
3. 책 상세 행동 버튼 설계
4. 개인화 추천 이유 응답 구조 설계
5. frontend/backend 검증 범위 확정
