## 앞으로 구현할 내용

### 1순위: 책 이미지 연동과 캐싱

현재 책 카드는 실제 표지 이미지가 아니라 카테고리 기반 색상 블록을 사용한다.
MVP에서는 외부 도서 API에서 표지 이미지를 가져오되, 매번 외부 API를 호출하지 않고 DB에 저장해 캐싱한다.

구현할 내용:

- 외부 도서 API 후보 비교
  - Kakao Developers 도서 검색 API
  - 네이버 개발자센터 책 검색 API
  - Google Books API
- 1차 추천 후보는 Kakao Developers 도서 검색 API로 둔다.
- 책 검색 API 응답의 `thumbnail` 또는 이미지 URL을 가져온다.
- `books.image_url`에 표지 이미지 URL을 저장한다.
- 이후 화면과 API 응답은 외부 API가 아니라 DB의 `image_url`을 사용한다.
- 이미지가 없는 책은 기존 카테고리 색상 표지 fallback을 유지한다.

권장 흐름:

1. 책 검색 API 호출
2. 응답에서 이미지 URL 추출
3. DB 저장
4. 이후 홈, 랭킹, 책 상세, 마이페이지에서는 DB 값만 사용

주의 사항:

- 외부 API key와 환경 변수 추가가 필요할 수 있으므로 구현 전 별도 승인이 필요하다.
- `books` 테이블에 `image_url` 컬럼이 없다면 DB schema 변경 승인이 필요하다.
- 단순 API 호출로 끝내지 말고 반드시 DB 캐싱을 기준으로 한다.
- 외부 API rate limit과 장애 시 fallback 동작을 고려한다.

상세 계획:

- `docs/plan/2026-04-28/priority-4-book-image-integration-plan.md`

### 2순위: 추천 이유 고도화와 추천 히스토리 저장

현재 추천 이유는 응답 생성 시점에 만들어지며, 추천 히스토리 저장 기준은 아직 정리되지 않았다.

구현할 내용:

- 관심 분야 기반 추천 이유 고도화
- 읽은 책 기반 추천 이유 고도화
- 저장한 책 기반 추천 이유 고도화
- 공통 키워드 기반 추천 이유 고도화
- 생성된 추천 이유를 `recommendations`에 저장하는 기준 정리
- 마이페이지 추천 히스토리에 개인화 근거를 더 구체적으로 표시

좋은 추천 이유 형식:

- "읽은 책 `조용한 투자 습관`과 투자, 습관 키워드를 공유합니다."
- "관심 분야로 선택한 경제 분야에서 최근 저장이 늘어난 교양서입니다."

### 3순위: 서비스 고유 기능 강화

계획 문서의 차별화 기능은 아직 별도 화면이나 컴포넌트로 닫히지 않았다.

구현할 내용:

- 교양 필터 리포트
  - 교양서로 분류된 이유
  - 제외 키워드가 없는 이유
  - 주요 카테고리와 키워드
  - 수험서, 문제집, 전공서 성격이 낮은 근거
- 추천 근거 카드
  - 관심 분야와의 연결
  - 읽은 책과의 연결
  - 저장한 책과의 연결
  - 최근 독서 트렌드와의 연결
- 읽을 책 결정 보조
  - 이 책을 읽기 좋은 사용자
  - 읽기 난이도
  - 예상 독서 분위기
  - 비슷한 책과의 차이

주의 사항:

- 새 데이터 필드가 필요한 항목은 먼저 현재 DB에 표현 가능한지 확인한다.
- 난이도, 분위기, 제외 근거는 데이터 출처가 불명확하면 정적 문구로 시작하지 않는다.

### 4순위: 검색 기반 책 추가

현재 온보딩의 읽은 책 입력은 backend가 제공하는 선택지 목록 기반이다.

구현할 내용:

- 읽은 책 검색 입력
- 저장한 책 검색 입력
- 검색 결과에서 읽은 책 또는 저장한 책으로 추가
- 검색 결과가 없을 때의 안내

backend 필요 API 후보:

- `GET /api/books/search?query=...`

주의 사항:

- 외부 도서 API 연동은 네트워크, API key, 데이터 저장 정책이 필요하므로 별도 범위로 분리한다.
- 우선 내부 DB 검색으로 시작한다.

### 5순위: 독서 목적 저장과 추천 반영

계획 문서에는 독서 목적 선택이 포함되어 있지만 현재 온보딩 저장 요청에는 없다.

구현할 내용:

- 독서 목적 선택 UI
- 독서 목적 저장 위치 결정
- 독서 목적 기반 추천 이유와 후보 조정

주의 사항:

- 현재 확인한 코드 기준으로 독서 목적 전용 schema는 없다.
- DB schema 변경 가능성이 높으므로 구현 전 별도 승인이 필요하다.

### 6순위: 데이터 기반 추천 확장

사용자 행동 데이터가 충분히 쌓인 뒤 진행할 항목이다.

구현할 내용:

- 행동 로그 기반 랭킹 개선
- 유사 도서 추천 개선
- 유사 사용자 추천
- 리뷰 또는 키워드 기반 감정 분석

주의 사항:

- 초기에는 데이터가 적어 추천 품질이 낮을 수 있다.
- MVP 이후 지표 수집 기준을 먼저 정해야 한다.

## 권장 구현 순서

1. 책 이미지 연동 API/provider 결정과 DB 캐싱 설계
2. 책 이미지 URL 저장 및 응답 반영
3. 추천 이유 응답 구조 고도화
4. 추천 히스토리 저장 기준 정리
5. 교양 필터 리포트와 추천 근거 카드 설계
6. 검색 기반 책 추가와 독서 목적 저장은 별도 계획으로 분리

## 검증 계획

문서만 변경할 때:

- 별도 빌드 검증은 필요하지 않다.
- 문서 링크와 변경 내용을 확인한다.

후속 frontend 변경 시:

```powershell
cd frontend
npm run build
```

후속 backend 변경 시:

```powershell
cd backend
.\gradlew.bat test
```

frontend/backend를 함께 변경할 때는 두 검증 명령을 모두 실행한다.

## 남은 리스크

- 책 이미지 연동은 외부 API key, rate limit, DB schema 변경 가능성이 있다.
- 추천 이유가 추상적이면 개인화 기능이 체감되지 않을 수 있다.
- 추천 히스토리 저장 기준을 정하지 않으면 마이페이지에서 과거 추천 근거를 재현하기 어렵다.
- 독서 목적과 난이도/분위기 정보는 현재 데이터 모델에서 바로 표현하기 어려울 수 있다.
