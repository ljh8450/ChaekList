# 1순위 구현 계획: 마이페이지 취향 관리 기능 보완

## 기준

- 작성일: 2026-04-28
- 상위 계획: `docs/plan/2026-04-28/follow-up-plan.md`
- 대상 항목: `1순위: 마이페이지 취향 관리 기능 보완`
- 목적: 마이페이지에서 사용자가 관심 분야와 읽은 책을 다시 관리할 수 있는 진입점과 빈 상태 안내를 추가한다.
- 범위: planner 역할 문서화만 수행한다. frontend/backend 코드, API, DB schema 변경은 포함하지 않는다.

## 현재 전제

- 마이페이지는 `frontend/src/pages/MyPage.jsx`에서 구현되어 있다.
- 온보딩 편집 화면은 `frontend/src/pages/OnboardingPage.jsx`에서 구현되어 있다.
- `/onboarding`은 이미 인증 사용자가 접근할 수 있는 라우트다.
- 온보딩 화면은 `GET /api/me/mypage`를 함께 호출해 기존 관심 분야와 읽은 책을 초기 선택값으로 채운다.
- 저장은 기존 `PUT /api/me/onboarding`을 사용한다.

## 구현 목표

1. 마이페이지에서 관심 분야 수정 진입 버튼을 제공한다.
2. 마이페이지에서 읽은 책 수정 진입 버튼을 제공한다.
3. 비어 있는 섹션에 다음 행동 버튼을 제공한다.
4. 온보딩 재진입 시 "처음 설정"이 아니라 "취향 수정" 흐름임을 명확히 보여준다.
5. backend API와 DB schema는 변경하지 않는다.

## 1차 구현 범위

### 1. 마이페이지 수정 진입점 추가

대상 파일:

- `frontend/src/pages/MyPage.jsx`

작업 내용:

- 관심 분야 섹션 우측에 `/onboarding`으로 이동하는 버튼을 추가한다.
- 읽은 책 섹션 우측에 `/onboarding`으로 이동하는 버튼을 추가한다.
- 버튼 문구는 기능을 직접적으로 드러낸다.
  - 관심 분야: `관심 분야 수정`
  - 읽은 책: `읽은 책 수정`
- 같은 `/onboarding`으로 이동하되, 필요하면 query string으로 의도를 전달한다.
  - 예: `/onboarding?section=interests`
  - 예: `/onboarding?section=read-books`

권장 방식:

- 1차에서는 별도 라우트를 추가하지 않는다.
- 기존 `/onboarding`을 재사용한다.
- `Link`를 사용해 이동만 처리하고 상태 저장 로직은 기존 온보딩 페이지에 둔다.

### 2. 마이페이지 빈 상태 안내 추가

대상 파일:

- `frontend/src/pages/MyPage.jsx`

작업 내용:

- `interestProfiles.length === 0`이면 관심 분야 카드 목록 대신 빈 상태를 표시한다.
- `readBooks.length === 0`이면 읽은 책 목록 대신 빈 상태를 표시한다.
- `savedBooks.length === 0`이면 저장한 책 영역에 빈 상태를 표시한다.
- `recommendationHistory.length === 0`이면 추천 히스토리 영역에 빈 상태를 표시한다.

권장 빈 상태 문구:

- 관심 분야: `관심 분야를 선택하면 추천 이유가 더 구체적으로 바뀝니다.`
- 읽은 책: `읽은 책을 추가하면 취향 분석에 반영됩니다.`
- 저장한 책: `나중에 읽을 책은 책 상세에서 저장할 수 있습니다.`
- 추천 히스토리: `추천 근거가 쌓이면 이곳에서 확인할 수 있습니다.`

권장 다음 행동:

- 관심 분야 비어 있음: `/onboarding`으로 이동하는 `관심 분야 선택`
- 읽은 책 비어 있음: `/onboarding`으로 이동하는 `읽은 책 추가`
- 저장한 책 비어 있음: `/rankings`로 이동하는 `읽을 책 찾기`
- 추천 히스토리 비어 있음: `/rankings`로 이동하는 `랭킹 보기`

주의 사항:

- 현재 책 상세 저장 기능은 아직 없으므로 저장한 책 빈 상태에서는 저장 동작을 약속하지 않는다.
- 문구는 짧게 유지하고, 긴 사용법 설명은 넣지 않는다.

### 3. 온보딩 재진입 UX 정리

대상 파일:

- `frontend/src/pages/OnboardingPage.jsx`

작업 내용:

- 기존 선택값이 있는 상태로 진입하면 화면 문구를 "개인화 시작"에서 "취향 수정"에 가깝게 조정한다.
- 저장 버튼 문구를 상황에 맞게 바꾼다.
  - 기존 선택값이 없으면 `저장하고 마이페이지로`
  - 기존 선택값이 있으면 `수정하고 마이페이지로`
- query string이 있으면 해당 섹션으로 사용자의 시선을 유도하는 정도만 반영한다.

권장 최소 구현:

- `selectedCategoryIds.length > 0 || selectedBookIds.length > 0` 여부로 편집 모드를 판단한다.
- 별도 backend 상태 API를 추가하지 않는다.
- 자동 스크롤이나 복잡한 단계형 UI는 1차 범위에서 제외한다.

### 4. 접근성과 로딩 상태 유지

대상 파일:

- `frontend/src/pages/MyPage.jsx`
- `frontend/src/pages/OnboardingPage.jsx`

작업 내용:

- 로딩 중에는 빈 상태가 먼저 깜박이지 않도록 `!isLoading` 조건에서만 빈 상태를 보여준다.
- 버튼은 링크 또는 button 역할이 명확하게 드러나게 구현한다.
- 기존 에러 메시지 흐름은 유지한다.

## 제외 범위

이번 1순위 구현에서는 다음을 제외한다.

- 새 backend API 추가
- DB schema 변경
- 독서 목적 저장
- 책 상세의 저장하기, 읽었어요, 관심 없음 버튼
- 저장한 책 삭제 또는 읽은 책 개별 삭제 API
- 검색 기반 책 추가
- 추천 알고리즘 변경
- 추천 히스토리 생성 로직 변경

## 예상 변경 파일

- `frontend/src/pages/MyPage.jsx`
- `frontend/src/pages/OnboardingPage.jsx`

추가 파일은 원칙적으로 만들지 않는다.
반복되는 빈 상태 UI가 과도하게 중복될 때만 기존 frontend 패턴을 확인한 뒤 작은 내부 helper 컴포넌트로 정리한다.

## 구현 순서

1. `MyPage.jsx`에 `/onboarding`과 `/rankings` 이동을 위한 `Link` import를 추가한다.
2. 관심 분야 섹션 헤더에 `관심 분야 수정` 링크를 추가한다.
3. 읽은 책 섹션 헤더에 `읽은 책 수정` 링크를 추가한다.
4. 관심 분야, 읽은 책, 저장한 책, 추천 히스토리 섹션에 빈 상태 분기를 추가한다.
5. `OnboardingPage.jsx`에서 기존 선택값이 있는 경우 편집 모드 문구와 버튼 문구를 조정한다.
6. 모바일/데스크톱에서 버튼과 빈 상태 문구가 겹치지 않는지 확인한다.
7. frontend 빌드를 실행한다.

## 검증 계획

frontend만 변경하는 계획이므로 구현 후 다음 명령을 실행한다.

```powershell
cd frontend
npm run build
```

수동 확인 항목:

- 마이페이지 관심 분야 섹션에서 수정 버튼이 보인다.
- 마이페이지 읽은 책 섹션에서 수정 버튼이 보인다.
- 관심 분야가 비어 있을 때 다음 행동 버튼이 보인다.
- 읽은 책이 비어 있을 때 다음 행동 버튼이 보인다.
- 저장한 책이 비어 있을 때 랭킹 이동 버튼이 보인다.
- 추천 히스토리가 비어 있을 때 랭킹 이동 버튼이 보인다.
- `/onboarding` 재진입 시 기존 선택값이 유지된다.
- 수정 저장 후 `/mypage`로 돌아온다.

## 리스크와 후속 작업

- 저장한 책 빈 상태는 책 상세 저장 기능이 아직 없으므로 `/rankings` 탐색으로만 연결한다.
- 읽은 책 개별 삭제는 현재 `PUT /api/me/onboarding`의 교체 저장 방식으로만 가능하다.
- 온보딩 화면을 편집 화면으로 계속 재사용하면 문구가 어색해질 수 있다. 이후 취향 관리 전용 화면이 필요해질 수 있다.
- 책 상세 행동 기능이 추가되면 저장한 책과 읽은 책 빈 상태의 다음 행동 버튼을 책 상세 또는 검색 흐름으로 다시 조정해야 한다.
