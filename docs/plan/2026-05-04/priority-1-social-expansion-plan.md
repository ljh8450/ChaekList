## 현재 정책 기준

### 공개 범위

- 사용자가 직접 공개한 게시글만 공개 피드와 검색에 노출한다.
- 공개 게시글이 있으면 별도 공개 프로필 설정 행이 없어도 공개 프로필 접근을 허용한다.
- 비공개 게시글은 feed/search/public profile에서 제외한다.
- 관리자 숨김 게시글은 feed/search/public profile에서 제외한다.
- 비활성화 계정의 공개 게시글은 숨긴다.
- 탈퇴 계정의 기존 공개 게시글은 삭제하지 않고 작성자 정보를 익명화한다.

### 대표 배지

- 대표 배지는 `badgesVisibility = PUBLIC`일 때만 공개 화면에 노출한다.
- 노출 위치:
  - 공개 피드 사용자명 앞
  - 공개 프로필 사용자명 앞
  - 공개 유저 검색 사용자명 앞
- 대표 배지명은 공개 유저 검색 조건에 포함하지 않는다.

### SNS 활동 성장 점수

- 월간 SNS 활동만 독서 성장 보조 점수로 반영한다.
- 활성 공개 게시글은 월 최대 5개까지 개당 2점으로 반영한다.
- 받은 좋아요는 월 최대 5개까지 개당 1점으로 반영한다.
- 삭제/관리자 숨김 게시글은 제외한다.
- SNS 활동 점수는 독서 활동 중심 성장 구조를 넘지 않도록 보조 점수와 상한을 유지한다.

### 알림

- 서버 저장형 알림 목록을 제공한다.
- 좋아요 알림은 게시글 작성자에게 생성한다.
- 신고 처리 상태 알림은 신고 상태가 실제로 변경된 경우 신고자에게 생성한다.
- 각 알림은 사용자 알림 설정이 켜져 있을 때만 생성한다.
- 실시간 push와 이메일 알림은 후순위다.

### moderation

- 1차는 사용자 신고 기반 수동 처리다.
- 관리자 API는 role 기반 관리자 권한으로 보호한다.
- 부적절한 닉네임은 사용자 신고에 따라 처리한다.
- 반복 게시 수량 제한은 두지 않는다.
- 생성/좋아요/추천 저장 등 주요 요청은 멱등성을 보장한다.

## 남은 SNS backend 구현 단위

### 1. 미디어 첨부

목표:

- 공개 게시글에 이미지 첨부를 지원할지 여부와 최소 정책을 정한다.

작업:

- 이미지 첨부 정책 수립
- 첨부 파일 개수 제한
- 첨부 파일 크기 제한
- MIME type 검증
- 저장소 결정
- 썸네일 생성 여부 결정
- 게시글 생성/조회 응답과 첨부 이미지 연결
- 신고/숨김 정책과 연결

주의:

- 스키마 추가 가능성이 높다.
- 저장소와 업로드 방식 결정 전에는 API 구현을 시작하지 않는다.

후순위:

- 영상 첨부
- 미디어 자동 moderation

### 2. 관리자 moderation 고도화

목표:

- 현재 신고 목록/상세/상태 변경/게시글 숨김을 넘어 운영 처리 이력을 남길 수 있게 한다.

남은 작업:

- 닉네임 신고 처리 액션
- 운영자 메모
- 반복 신고 남용 방지
- 신고 상태별 처리 이력

주의:

- 운영자 메모와 처리 이력은 스키마 추가 가능성이 있다.
- 닉네임 신고 처리는 사용자 계정 정책과 연결되므로 처리 방식 확정이 필요하다.

### 3. 서비스 공지 알림

목표:

- 시스템 또는 관리자가 서비스 공지성 알림을 생성할 수 있게 한다.

남은 작업:

- `SERVICE` 알림 생성 API
- 전체 사용자 대상 여부 결정
- 특정 사용자 대상 여부 결정
- `service_notifications_enabled` 설정 연동

주의:

- 단순 사용자별 알림 생성은 기존 `user_notifications`로 가능하다.
- 전체 공지의 발송 이력, 재발송, 대상 집계가 필요하면 별도 스키마가 필요하다.
