# MVP 구현 상태 및 확장 확인 문서

## 기준

- 작성일: 2026-04-30
- 최신화일: 2026-04-30
- 기준 문서:
  - `README.md`
  - `docs/plan/2026-04-30/follow-up-plan.md`
  - `docs/plan/2026-04-30/priority-1-social-expansion-plan.md`
- 목적: 1차 MVP 구현 상태와 남은 확장 확인 항목을 최신 상태로 정리한다.
- 범위: docs 역할 문서화만 수행한다. frontend/backend 코드, API, DB schema 변경은 포함하지 않는다.

## 구현 완료로 보는 항목

### 교양 전용 랭킹과 홈 피드

- 홈에서 현재 인기 책, 급상승 책, 카테고리별 랭킹을 표시한다.
- 랭킹 API는 최신 snapshot 기준 전체/카테고리/급상승 목록을 반환한다.
- 홈의 빈 데이터 fallback 문구가 정리되어 있다.
- 책 상세에서 교양 필터 리포트, 추천 근거, 읽을 책 결정 보조 섹션을 표시한다.

### 내부 DB 기반 책 검색과 책 추가

- `GET /api/books/search`가 내부 DB의 교양 필터 통과 책을 제목/저자로 검색한다.
- 온보딩과 마이페이지에서 `BookSearchPanel`을 통해 읽은 책/저장한 책을 검색해 추가할 수 있다.
- 기존 `/api/me/books/{bookId}/interactions` 흐름으로 `READ`, `SAVE`, `UNSAVE`, `DISMISS`를 저장한다.

### 독서 목적 저장과 추천 반영

- 온보딩 옵션에 독서 목적 후보가 포함된다.
- 사용자는 독서 목적을 1~3개 선택할 수 있다.
- `user_reading_purposes`에 목적이 저장되고, 마이페이지에서 조회된다.
- 홈 개인화 추천 점수와 reason에 독서 목적 기반 보조 근거가 반영된다.

### 개인 독서 성장/게이미피케이션 1차

- 마이페이지 응답에 `readingGrowth`가 포함된다.
- 월간 읽은 책 수, 저장 후 읽음 전환 수, 카테고리 다양성, 추천 전환 수를 계산한다.
- 대표 배지와 기본 배지가 계산된다.
- Header에는 로그인 사용자의 대표 배지가 표시된다.
- 마이페이지에 독서 성장 카드와 데이터 부족 상태가 표시된다.

## 남은 확장 확인 항목

### 1. Header 통합 검색

현재 상태:

- Header에는 검색 input이 있지만 검색 실행, 결과 페이지 이동, API 연결이 없다.
- 기존 책 검색은 온보딩/마이페이지의 책 추가 흐름에만 연결되어 있다.

확인할 것:

- Header 검색은 `docs/plan/2026-04-30/priority-1-social-expansion-plan.md`의 1순위 범위에서 처리한다.
- 최소 2자 검색어 제한, Enter 실행, 검색 결과 페이지 이동 방식을 확정한다.
- 책/저자/키워드/공개 게시물/공개 유저 결과의 노출 범위를 API 정책으로 고정한다.

### 2. 카카오 외부 책 검색과 선택 저장

현재 상태:

- 카카오 도서 검색 API는 책 표지 이미지 보강에만 사용된다.
- 로컬 DB에 없는 책을 사용자가 검색해 선택 저장하는 흐름은 없다.

확인할 것:

- `GET /api/books/search`가 내부 DB와 카카오 결과를 함께 반환할지 결정한다.
- 외부 결과 선택 시 별도 import API를 둘지, 기존 interaction API에서 import까지 처리할지 결정한다.
- ISBN13 기준 중복 확인, ISBN13 없는 결과 처리, 신규 책의 `is_general_eligible`, `filter_status`, `filter_reason` 초기값을 확정한다.
- 카카오 category를 ChaekList category로 매핑할지, 초기에는 `미분류` 또는 `PENDING`으로 둘지 결정한다.

권장 흐름:

1. 내부 DB 검색을 먼저 수행한다.
2. 내부 결과가 없거나 부족하면 backend에서 카카오 책 검색 API를 호출한다.
3. 내부 결과와 외부 결과를 공통 검색 결과 DTO로 내려준다.
4. 사용자가 외부 결과를 선택하면 ISBN13 기준으로 중복을 확인한다.
5. 기존 책이면 기존 book id를 사용한다.
6. 없는 책이면 `books`에 저장한다.
7. 이후 기존 interaction 흐름으로 `READ` 또는 `SAVE`를 저장한다.

### 3. 추천 산식 정리와 운영 데이터 확인

현재 상태:

- 개인 추천은 관심 분야, 읽은 책, 저장한 책, 독서 목적의 카테고리/키워드 기반 규칙 점수로 동작한다.
- `READ`, `DISMISS` 후보 제외 정책이 있다.
- 추천 결과는 `recommendations`에 `CONTENT_BASED` 유형으로 저장된다.

확인할 것:

- 추천 점수 가중치를 상수화하고 테스트 가능한 단위로 분리할지 결정한다.
- `VIEW`, `CLICK` 이벤트를 추천 산식에 반영할 만큼 충분히 수집되는지 확인한다.
- 추천 reason이 실제 점수 요인과 항상 일치하는지 테스트로 고정한다.
- `recommendations.reason`의 `VARCHAR(255)` 제약 안에서 근거 문구를 유지한다.
- snapshot 데이터가 운영에서 주기적으로 갱신되는지 확인한다.

## 구현 전 확장 확인 체크리스트

### API와 데이터 저장

- [ ] Header 통합 검색 API 응답 구조 확정
- [ ] 공개 게시물/공개 유저 검색의 개인정보 노출 범위 확정
- [ ] 카카오 책 검색 API key/env 이름 확정
- [ ] 외부 검색 결과 저장 시점 확정
- [ ] 외부 책 중복 기준 확정
- [ ] ISBN13 없는 책 처리 방식 확정
- [ ] 신규 외부 책의 교양 필터 초기 상태 확정
- [ ] 추천 reason 255자 제한 준수 방식 확인

### Frontend UX

- [ ] Header 검색 실행 방식 확정
- [ ] 검색 결과 없음/카카오 오류/짧은 검색어 문구 확정
- [ ] 검색 결과 페이지의 책/키워드/게시물/유저 섹션 순서 확정
- [ ] 중복 선택된 책의 disabled 또는 selected 상태 표시 방식 확정
- [ ] 모바일에서 검색 결과 목록과 기존 카드 그리드가 겹치지 않는지 확인

### 추천 품질

- [ ] 독서 목적이 추천 점수에서 보조 근거로만 쓰이는지 확인
- [ ] 추천 reason이 실제 점수 요인과 일치하는지 확인
- [ ] 후보 부족 시 fallback 추천이 자연스럽게 표시되는지 확인
- [ ] 추천 히스토리 reason과 홈 화면 reason이 충돌하지 않는지 확인
