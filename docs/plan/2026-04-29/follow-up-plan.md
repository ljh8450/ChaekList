## 남은 구현 계획

### 1순위: 개인 독서 성장/게이미피케이션 1차

목표:

- SNS보다 먼저 개인 기록을 더 자주 쌓게 만드는 마이페이지 중심의 성장 요약을 구현한다.
- 권수 경쟁보다 취향 발견, 분야 확장, 추천 전환 같은 개인 변화 지표를 보여준다.
- 별도 schema 없이 현재 `user_book_interactions`, `recommendations`, 카테고리/키워드 데이터로 계산 가능한 범위부터 시작한다.

상세 계획:

- `docs/plan/2026-04-29/priority-1-reading-growth-gamification-plan.md`

### 2순위: SNS 기능 확장

목표:

- 개인 성장 데이터가 쌓인 뒤 선택적으로 공유할 수 있는 공개 독서 활동 피드를 구현한다.
- 자유 게시글보다 구조화된 책/성장 카드 공유를 우선해 moderation 부담을 낮춘다.
- 공개 범위와 개인정보 노출 정책을 먼저 확정한 뒤 feed, like, public profile을 단계적으로 추가한다.

상세 계획:

- `docs/plan/2026-04-29/priority-2-social-expansion-plan.md`

## 권장 구현 순서

1. 마이페이지 계산형 독서 성장 카드
2. 기본 배지와 목적별 진행도
3. 월간/주간 요약 카드
4. 공개 범위 정책 설계
5. 구조화된 공유 게시글과 공개 피드
6. 좋아요와 공개 프로필
7. 신고/차단 등 moderation 기반

## 검증 계획

문서만 변경할 때:

- 별도 빌드 검증은 필요하지 않다.
- 삭제된 상세 계획 링크가 남아 있지 않은지 확인한다.

후속 frontend 변경 시:

```powershell
cd frontend
npm run build
```

후속 backend 변경 시:

```powershell
cd backend
.\gradlew.bat test
```

frontend/backend를 함께 변경할 때는 두 검증 명령을 모두 실행한다.

## 남은 리스크

- `docs/commands.md`는 현재 콘솔 출력에서 한글이 깨져 보인다. 문서 인코딩 정리가 별도 필요할 수 있다.
- 독서 성장 지표를 영구 저장하려면 schema 변경이 필요하므로 별도 승인을 받아야 한다.
- SNS 확장은 공개 범위, 삭제/비공개 전환, 신고/차단 정책이 확정되지 않으면 구현 리스크가 크다.
- 추천 이유는 여전히 `recommendations.reason`의 길이 제한 안에서 유지해야 한다.
- 현재 책 검색은 제목/저자 기반 내부 DB 검색이다. 키워드/카테고리 검색이나 외부 도서 API 연동은 별도 확장 범위다.
